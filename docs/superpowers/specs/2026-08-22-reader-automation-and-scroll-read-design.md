# 自动阅读与滚动标已读设计

## 状态

已完成交互设计确认，等待规格审阅。

## 目标

在现有的 RSS 阅读模式之上，补齐两项面向连续阅读的行为：

1. 用户可以为单个订阅源设定自动进入阅读模式。
2. 用户可以选择仅在读到 RSS 正文的一定进度后将文章标为已读。

设计参考 Reeder Classic 的内容优先原则，而不复制其视觉样式。MrRSS 保留现有的多栏工作流、RSS/网页/外部浏览器视图选择、卡片布局和手动已读操作。

## 当前约束

- `isReadingMode` 已是会话级 Pinia 状态；它只控制阅读壳层和焦点，不应被持久化为全局模式。
- 订阅源已有 `article_view_mode`，用于选择网页、RSS 渲染内容或外部浏览器。它描述内容视图，不应承担阅读壳层的语义。
- 文章在列表点击、键盘导航、详情导航和若干内容动作中会立即写入已读状态。启用滚动标已读后，这些入口必须遵循同一策略。
- `ArticleContent` 已拥有 RSS 正文滚动容器、滚动位置恢复和阅读进度计算，并同时服务标准详情页与卡片详情弹窗。
- 设置必须继续经 `internal/config/settings_schema.json` 和设置生成器维护；不手写重复的设置类型或默认值。

## 方案选择

### 不采用：扩展 `article_view_mode` 为 `reader`

该方案改动较小，但会把“在哪里获取/显示内容”和“是否隐藏导航并聚焦正文”混在一个枚举中。用户无法独立调整 RSS 渲染和阅读壳层，后续扩展也会继续耦合。

### 不采用：全局自动阅读模式

全局默认会突然改变所有订阅源的打开行为，难以满足新闻流、链接聚合和长文订阅源混用的场景。

### 采用：独立的订阅源偏好和阅读行为设置

新增订阅源级 `auto_reading_mode`，保留现有 `article_view_mode`。新增全局 `mark_read_on_scroll`，默认关闭，并使用固定、可解释的进度阈值。两项偏好分别表达“该订阅源如何阅读”和“何时确认读过”，不会改变未启用用户的现有行为。

## 持久化模型

### 订阅源自动阅读

- `feeds` 增加 `auto_reading_mode BOOLEAN NOT NULL DEFAULT 0`。
- `internal/models.Feed`、前端 `Feed` 类型、创建/更新请求和所有查询扫描路径同步增加 `auto_reading_mode`。
- 数据库初始化和迁移以默认值 `0` 补齐既有数据库；已有订阅源不发生行为变化。
- 编辑订阅源的高级设置增加“自动进入阅读模式”开关，默认关闭。
- 此开关只影响标准文章详情页的初始阅读壳层，不改变保存的 RSS、网页或外部浏览器内容视图偏好。

### 滚动标已读

- 设置架构新增 `mark_read_on_scroll`，类型为布尔值，默认 `false`，归类到 `reading`。
- 通过设置生成器更新 Go 配置、默认值、前端 `SettingsData`、自动保存载荷及数据库默认设置；不维护手工副本。
- 阅读设置的交互区域增加一个开关，说明为“读到正文 50% 后标为已读”。
- 阈值固定为 `50%`，不增加第二个数字输入项。固定阈值避免将常用阅读偏好变成难以理解的高级参数。

## 自动阅读生命周期

### 判定优先级

1. 订阅源配置为 `external` 时，外部浏览器优先。文章仍按现有规则立即标已读，且不进入应用内阅读模式。
2. 对其他订阅源，`auto_reading_mode=true` 表示该订阅源在 RSS 内容可用时自动进入阅读壳层。
3. 若 RSS 内容为空、加载失败，或请求完成前用户已切换文章，系统回退到正常的有效内容视图，不进入阅读模式、不移动焦点，也不显示重复提示。
4. 手动选择原网页会在当前文章退出阅读模式，且不会被同一篇文章的自动规则重新覆盖。
5. 手动退出阅读模式只影响当前文章。选择或导航到同一订阅源的下一篇文章时，自动规则会再次生效。

外部浏览器和自动阅读互斥。在订阅源编辑界面中，`external` 视图激活时自动阅读开关禁用并说明外部浏览器优先；已保存的自动阅读偏好保留，以便用户切回应用内 RSS 视图时恢复。

### 标准详情页和卡片布局

- 选择启用自动阅读的订阅源文章时，自动阅读优先于卡片布局，文章进入标准详情页。这样用户对该订阅源的明确阅读意图不会被全局卡片布局稀释。
- 未启用自动阅读的卡片布局保持现有弹窗体验；若显示 RSS 正文，它仍参与滚动标已读策略。
- 现有手动阅读模式入口、快捷键、首次 Escape 退出和正文焦点规则保持不变。

### 异步与焦点

`useArticleDetail` 保留文章 ID 作为加载令牌。只有加载完成后令牌仍匹配当前文章、RSS 内容非空且订阅源满足自动规则时，才依次显示 RSS 内容、设置 `isReadingMode`，并由 `ArticleContent` 在渲染完成后把焦点交给正文滚动区域。任何过期请求都不得改变当前文章的视图或焦点。

## 已读策略

### 行为矩阵

| 场景 | `mark_read_on_scroll=false` | `mark_read_on_scroll=true` |
| --- | --- | --- |
| 应用内 RSS 正文（标准详情或卡片弹窗） | 打开即标已读，保持现状 | RSS 正文到达或恢复到 `>=50%` 时标已读 |
| 应用内原网页 iframe | 打开即标已读 | 打开即标已读 |
| 外部浏览器 | 打开即标已读 | 打开即标已读 |
| 悬停、手动切换已读、上下文菜单的明确已读操作 | 保持即时 | 保持即时 |
| 图片画廊等非正文浏览面 | 保持现状 | 保持现状 |

### 统一执行路径

新增小型文章已读策略 composable，负责：

- 根据文章实际打开的表面（RSS、网页、外部）判断是否应延迟；
- 将“打开即已读”与“达到阈值后已读”写入同一 `markAsRead` 方法；
- 对每篇文章维护一次进行中的写入，避免连续滚动产生重复请求；
- 成功后刷新未读和筛选计数；
- 失败时仅在没有后续手动状态变化的情况下还原乐观更新，并允许下一次进度事件重试。

`ArticleList`、键盘文章导航和 `useArticleDetail` 不再各自决定 RSS 正文的即时已读时机；它们只选择文章或调用该策略。列表在未读筛选下仍临时保留当前阅读文章，避免文章达到阈值后从当前列表突然消失。

### 进度来源

`ArticleContent` 继续拥有滚动位置持久化和进度计算，但会为所有 RSS 正文表面报告进度，不只在阅读壳层开启时报告。标准详情页和卡片详情弹窗各自将该事件交给统一策略。

- 进度达到 `>=50%` 时触发一次。
- 不可滚动的短文章在正文完成布局后报告 `100%`，因为完整内容已经可见。
- 恢复到已保存的滚动位置也会报告进度；恢复位置达到阈值代表用户此前已经读到该位置。
- 加载中、空内容、原网页 iframe 和已经已读的文章不会触发滚动标已读。

## 组件边界

- `internal/database`、`internal/models`、`internal/handlers/feed`：持久化和传输 `auto_reading_mode`，不处理前端阅读生命周期。
- `internal/config/settings_schema.json` 和生成输出：唯一的 `mark_read_on_scroll` 设置定义与默认值来源。
- `FeedFormModal` 与其 `AdvancedSettings` 子组件：展示订阅源级自动阅读偏好和与外部浏览器的互斥说明。
- `InteractionSettings`：展示全局滚动标已读开关。
- `useArticleDetail`：解析有效内容视图、应用自动阅读、处理文章切换竞态和标准详情页的已读策略入口。
- 新的文章已读策略 composable：集中判断、请求去重、乐观更新和计数刷新。
- `ArticleContent`：只计算和报告 RSS 正文进度，保留滚动位置与焦点职责。
- `ArticleDetail` 与 `ArticleDetailModal`：把各自的 RSS 进度传递给已读策略；不自行重复网络写入逻辑。
- `ArticleList` 和键盘快捷键：保留选择与外部浏览器行为，但不在可延迟的 RSS 场景提前标已读。

## 错误处理与可访问性

- 自动阅读不会把加载错误包装成新的弹窗；现有内容错误和重试界面仍是唯一反馈。
- 开关的名称和说明使用中英文国际化字符串，外部浏览器互斥状态对键盘与辅助技术可感知。
- 自动进入后只在 RSS 正文准备就绪时移动焦点；不会抢夺查找、图片查看器、模态框或用户明确切换到原网页后的焦点。
- 已读状态变更沿用当前视觉与读屏状态；本功能不以颜色作为唯一反馈。

## 测试与验证

### 后端与设置

- 覆盖既有数据库升级后 `auto_reading_mode` 的默认值、创建、更新和读取。
- 运行设置生成器并验证 `mark_read_on_scroll=false` 出现在后端和前端生成的默认值与载荷中。

### 前端单元与组件测试

- 订阅源表单正确保存自动阅读偏好，并在外部浏览器模式下禁用该控件。
- 自动阅读仅在当前文章的有效 RSS 内容加载完成后进入；空内容、加载失败和过期请求不进入。
- 自动阅读覆盖卡片布局；手动退出只影响当前文章，下一篇同订阅源文章再次自动进入。
- 开关关闭时选择 RSS 文章仍立即标已读。
- 开关开启时，RSS 正文在 `49%` 不标记、`50%` 标记一次；短文章与恢复的高进度位置标记一次。
- 原网页、外部浏览器、悬停和手动已读操作在开关开启时仍立即执行。
- 请求失败后恢复状态并允许后续进度重试；已读计数和未读筛选中的当前文章保持一致。
- `ArticleContent` 在标准详情与卡片详情中都报告进度，且现有阅读模式焦点和工具栏进度不回归。
- 新增和修改的文案在英语与简体中文 locale 中完整存在。

### 集成验证

- 在桌面、紧凑布局与移动宽度验证一个自动阅读订阅源和一个普通订阅源的打开行为。
- 验证阅读模式焦点、首个 Escape、正文滚动、返回原网页、外部浏览器与文章前后导航。
- 验证未读筛选下达到阈值后的选中文章仍保持可见，切换文章后再按现有规则移除。
- 运行相关 Vitest、完整前端测试、前端生产构建、Go 测试和 `wails3 build`。

## 非目标

- 不增加全局“默认自动阅读模式”。
- 不提供可调的滚动阈值、按账户的独立阈值或阅读时间统计。
- 不改变 RSS 抓取、全文提取、翻译、摘要、主题或已有阅读模式的快捷键语义。
- 不模仿 Reeder 的品牌、视觉资源或专有交互细节。
