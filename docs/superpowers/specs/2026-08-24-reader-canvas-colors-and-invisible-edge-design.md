# 阅读画布颜色与无形边缘导航设计

## 背景与已确认决策

阅读模式目前已经能持久化本机字体、字号、行高、段距与正文宽度，但正文的背景和文字颜色仍完全继承应用主题。用户需要在阅读模式中自行定义这两种颜色，同时不能把工具栏、文章列表或应用侧栏误染成阅读配色。

桌面阅读模式左侧目前的“条”也已定位：`App.vue` 为鼠标靠左展开文章列表保留了一个宽 `16px` 的固定触发区，而该触发区使用了 55% 强调色和 0.7 透明度。因此它不是未隐藏的文章列表，而是一个被错误地视觉化的悬停热区。

已确认采用方案 A：

- 自定义颜色仅作用于文章阅读画布与文章文字；应用工具栏、文章列表、主侧栏和阅读外观面板继续使用应用主题。
- 左缘仍可通过鼠标进入展开文章列表，但默认不显示任何色条、阴影或把手；仅键盘聚焦时提供可见焦点反馈。

本设计补充而不取代 `2026-08-24-reader-typography-refresh-design.md`：其字体与节奏决策保持有效；本规格为它加入受限、可读的颜色层。

## 目标与非目标

### 目标

1. 读者可以在阅读中的 `Aa` 面板及“设置 → 阅读”中选择正文背景色和正文文字色，当前文章即时预览并持久化到后续文章。
2. 默认状态始终跟随当前应用主题；切换 Paper、Ink、Sepia、高对比度或自定义应用主题时，不会覆盖字体排版，也不会保留过时的主题色副本。
3. 自定义配色必须保持正文前景与背景至少 4.5:1 的 WCAG 正文对比度，且不允许透明颜色。
4. 鼠标移到桌面最左侧仍可临时展开文章列表，但收起后视觉上没有可见色条。

### 非目标

- 不为单篇文章、单个订阅源或临时会话保存不同配色。
- 不修改应用主题编辑器、工具栏、主侧栏、文章列表、链接预览页或系统窗口背景。
- 不支持透明色、CSS 任意表达式、图片背景、渐变、远程主题或字体下载。
- 不新增移动端左缘手势；移动端保留既有抽屉和触摸目标。

## 设置模型与持久化

在 `internal/config/settings_schema.json` 的 `reading` 分类中增加两个字符串设置，并运行既有生成器更新所有生成产物：

| 设置键 | 前端键 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `content_background_color` | `contentBackgroundColor` | `""` | 空值表示跟随应用主题；否则为规范化的 `#rrggbb` 阅读画布背景。 |
| `content_text_color` | `contentTextColor` | `""` | 空值表示跟随应用主题；否则为规范化的 `#rrggbb` 正文文字颜色。 |

两个字段是一个颜色模式，而不是两个可独立混搭的主题覆盖：

- 两者均为空：**跟随应用主题**，正文使用现有主题的 `bg-primary` 与 `text-primary`。
- 两者均为有效不透明 `#rrggbb`：**自定义阅读画布**。
- 迁移、手工 API 请求或旧数据出现仅一个非空、格式不合法、含 alpha 的组合时，前端和后端都将该组合归一为“跟随应用主题”，而不是在不确定背景上猜测可读性。

后端继续通过设置系统存储值，但在保存入口补充阅读颜色的白名单校验：只接受空字符串或 `#RRGGBB`，存储时转为小写。前端同样在纯函数边界进行归一化，不能仅依赖原生颜色控件。

## 信息架构与交互

### 阅读外观面板

由于 `Aa` 面板同时承载排版和颜色，用户可见名称从“阅读排版”改为“阅读外观”（英文为 “Reading appearance”）。已有字体、字号、阅读节奏、宽度和真实预览顺序不变；在正文宽度之后、真实预览之前加入“阅读颜色”区：

1. **跟随应用主题 / 自定义阅读画布**：分段选择，状态不能只靠色块区分。
2. 启用自定义时显示两个并排但可换行的控件：**背景色**与**正文色**。每个控件包含系统颜色选择器、可键盘编辑的 `#RRGGBB` 文本值、色样和清楚的标签。
3. 显示“正文对比度：x.xx:1”。达到 4.5:1 时给出可读状态；低于阈值时显示明确警告和修复提示。
4. 真实预览使用同一套画布变量，因此预览、当前文章和保存结果一致。

从“跟随应用主题”切换到“自定义阅读画布”时，控件以当前**解析后的**主题背景和文字颜色作为初始值，避免突然切成黑白默认色。切回跟随主题时立即清空两个保存字段并恢复主题色。

颜色调整沿用现有 500ms 合并自动保存：

- 有效且对比度达标的颜色立即更新当前文章、预览和共享设置，并排队保存。
- 对比度不足的草稿仍在面板中供用户修正和预览，但不写入共享设置或后端；面板关闭、主题切换或 Escape 后丢弃该无效草稿并保留上一次有效配色。
- 保存失败时沿用现有错误提示、实时预览和重试操作；重试仅提交最后一组有效完整配色。

“恢复默认排版”仍只恢复五项字体排版，不会悄悄清除用户的颜色。颜色区单独提供“颜色跟随主题”操作，避免一个恢复动作破坏不相关偏好。

### 设置页

“设置 → 阅读”的字体排版页使用与 `Aa` 面板相同的颜色控件与设置模型，不复制验证或色值格式化逻辑。桌面与手机的阅读内面板都显示颜色控制；仅正文宽度继续在手机隐藏。

## 文章画布应用

新增独立的纯前端阅读画布模型（例如 `readerCanvas.ts`），不将非排版颜色混入 `readerTypography.ts`。它负责：

- 校验、规范化和识别“跟随主题 / 自定义画布”状态；
- 从两个安全字段产生局部 CSS 变量；
- 计算不透明背景和正文色的对比度；
- 为颜色控件提供当前主题色的安全初始值。

`ArticleContent` 的阅读区域将成为唯一的画布变量作用域。自定义配色须覆盖：文章滚动背景、正文、标题、元数据、摘要、引用、代码、列表标记和续读提示；次级文字、边框、弱表面和代码背景由正文色与背景色以受限的 `color-mix()` 派生，避免只改正文后其余内容不可见。链接与语义状态仍使用应用强调色和状态色，不伪装成普通正文。

实现不得通过重写文档根部的 `--bg-primary` 或 `--text-primary` 达到这一效果，以免泄漏到阅读工具栏、文章列表或 Teleport 面板。颜色变量只挂在 `ArticleContent` 根阅读区域及其子树；文章工具栏是其兄弟节点，继续继承应用主题。嵌入 iframe、图片和视频不强制重着色。

## 无形左缘文章列表

桌面阅读模式继续只临时展示**文章列表**，不展开全局主侧栏或订阅抽屉。现有 `useSidebarEdgeReveal` 的 180ms 离开宽限、焦点留存、触摸禁用及“选中另一篇文章立即收起”规则保持不变。

调整呈现方式如下：

- 固定左缘热区仍有足够稳定的命中宽度（实现时可保持 16px），但静止状态的 shell、按钮、背景、边框和阴影全部透明。
- 进入热区时才将文章列表从左侧展开；展开后的列表使用现有应用主题背景与阴影，并不使用阅读自定义颜色。
- 热区保留真实、有标签的按钮，便于屏幕阅读器和键盘使用。`focus-visible` 时显示清晰的焦点轮廓并立即展开列表；普通鼠标静止、离开和收起后绝不显示持久色条。
- 热区不拦截移动端触摸事件，不影响文章横向内容、正文选词或链接点击；鼠标指针在命中区可显示东向调整提示。
- 遵守 `prefers-reduced-motion`；用户选择文章、离开区域或焦点离开后均维持现有可预测的收起时机。

## 无障碍、国际化与失败处理

- 中英文均补充“阅读外观”“阅读颜色”“跟随应用主题”“自定义阅读画布”“背景色”“正文色”“颜色跟随主题”“正文对比度”以及对比度不足提示。
- 颜色选择器具有可读标签、当前色值和非颜色唯一的模式/有效状态。色样不是唯一的信息来源。
- 颜色对比度阈值为 4.5:1，明确适用于一般正文；无效色值、透明色和不完整配色绝不发往后端。
- 若系统颜色选择器不可用，严格格式的文本输入仍可操作；若当前主题色无法解析为安全初始值，则保留跟随主题模式并显示可恢复错误提示，而非生成猜测色。
- 左缘隐藏热区不应制造键盘焦点陷阱：焦点移入展开、焦点移出延迟收起；屏幕阅读器可找到“显示文章列表”按钮。

## 测试与验收

### 单元与组件测试

- 阅读画布纯函数覆盖空值、完整有效 HEX、单字段/透明/非法值回退、规范化、主题色初始值与 4.5:1 对比度边界。
- 设置生成与后端保存测试覆盖两个新键、默认值、合法完整对、拒绝不完整或非法请求，以及重新读取后的值。
- 阅读偏好组合式函数测试颜色与排版同样可合并自动保存、无效草稿不发请求、有效修正后只保存完整对、失败重试使用最后有效状态。
- `ReaderAppearancePanel` 和设置页测试模式切换、两个颜色控件、色值标签、对比度提示、跟随主题清除操作、手机可访问性和现有字体控件无回归。
- `ArticleContent` 测试阅读画布变量只出现在内容区域，标题/正文/摘要预览采用它们，而阅读工具栏仍保留应用主题变量。
- `App` 测试仍可从桌面左缘进入展开文章列表、离开/选文后收起、键盘焦点可见；同时以样式或 DOM 断言保证收起热区没有背景、阴影、边框或可见宽度效果。
- 回归现有阅读链接预览及“返回阅读界面”流程，确保颜色层不会影响覆盖层与焦点恢复。

### 人工验收与构建

1. 在 Paper、Ink、Sepia、高对比度及一个自定义应用主题中验证“跟随应用主题”。
2. 选择一组可读的自定义背景/文字色，确认当前文章、下一篇文章、摘要、标题、代码和续读提示一致；工具栏和文章列表不变色。
3. 尝试低对比度、透明或不完整值，确认可修正但不会持久化；关闭后恢复上一次有效状态。
4. 进入阅读模式后观察左侧：收起时无条；鼠标到最左缘展开文章列表；键盘 Tab 可找到并操作它；移动端没有误触触发。
5. 运行相关 Vitest、完整前端测试、前端生产构建、`go test -v -timeout=5m ./...` 和 `wails3 build`。若用户要求安装，使用验证通过的新构建覆盖 `/Applications/MrRSS.app`。
