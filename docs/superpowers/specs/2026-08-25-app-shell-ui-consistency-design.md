# 应用壳层视觉一致性设计

## 已确认边界

本次覆盖 MrRSS 的全部应用界面，而不只限于主阅读区：主界面的活动栏、订阅抽屉、
文章列表、文章工具栏、图片画廊，以及所有通用与业务弹窗、设置页面和其中的工具栏。

本次不改变功能、路由、数据流、文案、主题 token、阅读正文排版偏好或用户保存的
阅读器字体设置。文章正文、代码块和站点原始内容继续由既有阅读器样式控制；统一的
是应用操作界面的结构、控件和信息层级。

## 根因与目标

当前顶部区域、按钮与标题的视觉不一致来自重复的局部实现：各组件分别使用不同的
`p-*`、`text-*`、图标尺寸和局部 `.btn-*` 规则。相同语义的 Header 既有 `p-2 sm:p-4`
也有 `p-3 sm:p-5`，图标按钮则混用内容撑开的 padding、36px 和 44px 固定尺寸。
因此任意一个组件的文本行高或图标尺寸变化都会改变边框位置，且同类按钮无法保持
一致。

目标是在不重构业务组件树的前提下，建立一套由共享 CSS 令牌和语义类表达的应用壳层
规范。所有 Header 的边界、控件尺寸和文字角色从同一来源派生；业务组件只选择语义，
不再自行组合一套新的几何规则。

## 共享结构规范

### Header

定义两类顶栏：

| 语义 | 适用位置 | 桌面 | 窄屏 / 触控 |
| --- | --- | --- | --- |
| `app-panel-header` | 三栏主界面、订阅抽屉、文章列表、文章工具栏、图片画廊 | 固定 `56px` 高 | 最小 `52px` 高 |
| `app-modal-header` | `BaseModal`、设置模态框及所有业务弹窗 | 固定 `64px` 高 | 最小 `56px` 高 |

两类 Header 都使用同一条 `1px solid var(--border-color)` 底边，并通过
`box-sizing: border-box` 将边框计入高度。Header 本身负责背景、横向内边距、水平
flex 对齐与底边；子元素不得再用外边距、独立纵向 padding 或伪元素移动边界。

主界面在桌面上采用 `56px` 的共同高度，因此相邻的侧栏、列表和内容面边框位于同一
水平基线。移动端保持至少 52px 的视觉区，以在压缩空间中仍可容纳 44px 触控目标和
上下间距。弹窗 Header 的高度单独略大，用于容纳标题、描述性 slot 或关闭操作，
但其边框、内边距逻辑与主界面使用相同的规则。

### 按钮

共享按钮只表达尺寸与交互角色，颜色仍沿用当前主题语义 token：

| 语义 | 桌面尺寸 | 窄屏 / 触控尺寸 | 使用场景 |
| --- | --- | --- | --- |
| `ui-button` | `36px` 高 | `44px` 高 | 保存、取消、测试、添加等普通操作 |
| `ui-button--compact` | `32px` 高 | `36px` 高 | 表格行、密集设置和行内操作 |
| `ui-icon-button` | `36 × 36px` | `44 × 44px` | Header、抽屉、工具栏和弹窗中的仅图标操作 |

所有按钮使用一致的圆角、`font-medium`、`inline-flex` 对齐、键盘焦点轮廓、禁用态和
150–200ms 的颜色过渡。主、次要、危险等按钮变体只改变前景、背景和边框，不再重复
定义高度、padding 或字重。Header 内的图标按钮始终使用 `ui-icon-button`，避免图标
本身或 text padding 决定控件外框。

### 字体层级

应用 UI 使用明确、有限的五级文字角色：

| 角色 | 规格 | 典型位置 |
| --- | --- | --- |
| 页面标题 | `text-lg`、`font-semibold` | 文章列表、图片画廊、订阅抽屉标题 |
| 模态标题 | `text-xl`、`font-semibold` | 设置与业务弹窗标题 |
| 区块标题 | `text-sm`、`font-semibold` | 设置分组、侧栏分组和卡片小标题 |
| 控件 / 正文 | `text-sm`、`font-medium` 或常规字重 | 按钮、输入、菜单和说明正文 |
| 辅助信息 | `text-xs`、`font-medium` | 元数据、计数、提示和键盘说明 |

使用现有 `--ui-font-scale`，所以用户的全局 UI 字号设置继续线性影响所有角色。禁止为
同一语义在不同组件中混用 `font-bold`、`font-semibold`、`text-base` 和 `text-lg`；
视觉强调应来自定义好的角色，而不是局部加粗。

## 实现边界与迁移策略

1. 在 `frontend/src/style.css` 建立壳层尺寸令牌和共享语义类，包括 Header、按钮、标题、
   焦点、禁用和紧凑变体。令牌只引用既有主题变量，不新增或覆盖主题配色。
2. 将主三栏与图片画廊的顶栏迁移到 `app-panel-header`，移除决定高度的局部 padding 和
   不一致标题字重；文章工具栏现有阅读模式的特殊布局保留，但不再破坏边框基线。
3. 将 `BaseModal` 和 `SettingsModal` 的顶栏迁移到 `app-modal-header`，让通过 slot 提供的
   标题与默认标题使用相同的层级。业务弹窗只保留内容特有的 icon、标题和副标题。
4. 将局部 `.btn-primary`、`.btn-secondary`、`.btn-danger` 和 Header 专属 icon button 迁移到
   `ui-button` / `ui-icon-button` 的结构类及颜色变体。仅在组件确有密集表格或行内语境时
   使用 compact 变体。
5. 对设置页、发现、筛选、规则、更新、订阅管理和文章辅助面板逐一迁移；不把文章正文
   中的链接、媒体控制或第三方嵌入误替换为应用按钮。

不引入 `BaseHeader` 或 `BaseButton` Vue 组件。本次的漂移是样式所有权问题，CSS 语义类
已足以统一几何且不会扰动现有事件、slot、测试选择器和可访问性语义。

## 可访问性与响应式要求

- 触控宽度下所有 Header 操作保持至少 44px 的可点击区域；桌面密度保持 36px，不让
  触控需求挤占阅读空间。
- 图标按钮保留现有的 `title` / `aria-label`；迁移不得把图标替换为无名称的交互元素。
- 共享 `:focus-visible` 轮廓使用主题强调色，与 High Contrast 主题兼容；禁用态保留
  `cursor-not-allowed` 与足够可辨识的透明度。
- Header 内标题可截断但不与操作区重叠；窄屏标题容器可收缩，操作区不缩小到触控目标
  以下。
- 所有共享色值只使用已有语义 token，确保 Paper、Ink、Sepia、高对比度和自定义主题
  无需迁移即可继承同一布局。

## 验收与验证

### 自动化验证

1. 为共享壳层样式增加源级/组件回归测试，断言主三栏、图片画廊、通用模态框和设置模态
   框使用对应的 Header 语义类，且不保留会改变高度的旧顶栏 padding 组合。
2. 扩展关键 Header 组件测试，验证标题角色、图标按钮语义、边框类和移动端触控尺寸契约。
3. 为设置控件与业务弹窗按钮增加样式契约测试，验证普通、紧凑、图标与危险变体采用
   共享结构类而不是组件私有 `.btn-*` 几何规则。
4. 运行相关 Vitest、完整前端单元测试、ESLint、Prettier、Vite 生产构建、`git diff --check`
   与 `wails3 build`。

### 人工验证

在 1440px、1024px 和 390px 宽度下检查 Paper、Ink、Sepia 与 High Contrast：三栏顶部
边框完全共线；抽屉、画廊和弹窗的边界完整；所有 Header 图标按钮等大且容易点击；
标题、分组、控件文字和辅助信息一眼可区分；阅读模式及用户选择的阅读正文排版不变。
