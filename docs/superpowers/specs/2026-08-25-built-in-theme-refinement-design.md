# 内置主题视觉体系优化设计

## 已确认边界

本次只优化既有的四个内置主题：`paper`、`ink`、`sepia` 与
`high-contrast`。不新增预设，不修改它们的 ID、持久化值、`ThemePreset`
类型或自定义主题档案格式。

`Auto` 仍按系统外观在 Paper 与 Ink 间解析；旧的 `light` / `dark` 值仍
分别规范化为 `paper` / `ink`。自定义主题继续从其 `basePreset` 继承未覆盖
的 token，因此新的基础配色会自然改善已有自定义档案，而用户明确保存的
覆盖值保持不变。

主题负责应用外壳、阅读器表面与语义状态。阅读排版、阅读画布的“跟随应用
主题 / 自定义阅读画布”模式、文章自定义 CSS 和字体选择均不在本次改动范围。

## 设计目标

MrRSS 是一款每天多次打开、长时间扫读与深读的桌面应用。主题应为工作流
提供稳定的环境，而不是用装饰竞争文章内容。四套预设分别回答四种真实场景：

| 预设 | 使用场景 | 视觉任务 |
| --- | --- | --- |
| Paper | 日间桌面阅读、管理订阅、快速分拣 | 清晰、冷静、轻量的工作台。 |
| Ink | 弱光环境、夜间连续阅读 | 低眩光的深石墨层次，避免纯黑压迫感。 |
| Sepia | 长文、评论与慢速阅读 | 低饱和暖灰与棕褐节奏，不做泛黄“纸张特效”。 |
| High Contrast | 辅助阅读、极高可见性需求 | 严格黑白结构，黄色仅标识焦点与当前操作。 |

所有主题采用同一套“背景 → 侧栏 → 面板 → 悬停 → 选中”的空间层级和同一套
语义状态词汇。强调色只用于主操作、当前选择、键盘焦点和链接，不用作非活动
区域的装饰色。

## 核心令牌方案

定义，避免改变 `customTheme.ts` 的安全解析边界；不引入任意 CSS 色值。

### 各主题细节

#### Paper：日间工作台

- 使用偏蓝的中性白，而不是纯白和深蓝的强对比组合；侧栏比内容面略深，建立
  结构但不形成明显色块。
- 选中项以浅蓝表面和蓝色文字共同表达，不能只依赖背景色。
- 状态色保持独立语义：警告为低饱和琥珀、成功为绿色、危险为红色；它们不借用
  品牌蓝作为所有状态。

#### Ink：低眩光夜读

- 背景、面板与侧栏分别落在黑灰、石墨与蓝灰三个清晰层级；没有纯黑的大面积
  非高对比度表面。
- 蓝色强调只用于已选导航、焦点与可操作文字，阅读文本使用接近白的中性灰。
- 媒体遮罩、代码面与悬浮层使用近黑而非高饱和蓝，避免夜间屏幕产生漂浮光晕。

#### Sepia：克制长读

- 背景从偏黄的“旧纸”收敛为暖灰；面板与侧栏只保留足够的棕褐差异来维持层级。
- 陶土强调色承担链接、主按钮和选中标识；不把暖色扩散到正文、边框或所有状态。
- 代码、表格条纹和媒体遮罩沿用较深的褐灰基底，确保技术文章和嵌入内容仍然清晰。

#### High Contrast：严格可见性

- 黑白负责结构和正文；边界保持纯白以保留组件边缘。
- 黄色只承担键盘焦点、强调操作、选中项和高亮，绝不作为大面积填充或普通正文色。
- 信息、成功、警告和危险各保留独立且可辨识的前景/背景对；文字、图标、边框与
  标签共同表达状态，不能只依靠颜色。

## 主题选择器

`ThemePresetPicker` 继续是单一、可键盘操作的 `radiogroup`，不改变选项顺序：
Auto、Paper、Ink、Sepia、高对比度，然后是用户自定义主题。

当前的三条色带预览改为紧凑的“应用壳”缩略图：左侧为活动栏/订阅区域，右侧为
内容面，包含一条选中导航、两条中性正文线和一个强调操作点。它呈现的是用户
实际会感知到的层级关系，而不是孤立色块。缩略图只作辅助，主题名称、说明、
单选状态和勾选图标仍是完整可访问的信息来源。

- Auto 仍占满一行，并展示相邻的 Paper 与 Ink 小壳预览，明确说明它会随系统
  外观改变，而不是生成第五套颜色。
- 四个内置主题维持两列布局；窄屏回退为单列。选项卡圆角、边框和交互尺寸继续
  使用现有设置控件词汇，不引入新的卡片语言。
- 选中态使用强调色边框、内描边与勾选图标；悬停只改变表面色；焦点使用清晰的
  2px 轮廓。色彩转换仅用于局部 hover/focus，时长 150–200ms，并尊重
  `prefers-reduced-motion`；切换整个应用主题时不做全局过渡。
- 预览颜色必须与 CSS 根令牌使用相同的核心锚点。若以后改动预设颜色，预览测试
  要求同步修改，避免“看见一种主题、应用另一种主题”。

## 兼容性与边界

- `themeBackgroundColors` 必须同步为每套新 `--bg-primary`，保证文档根节点、
  `body`、原生滚动区和窗口背景无闪烁地一致。
- `resolveThemePreset()`、`isDarkThemePreset()`、`normalizeThemePreference()` 与
  `builtInThemePresets` 的行为不变；Ink 与高对比度仍使用暗色 `color-scheme`。
- 自定义主题仍以四套完整预设之一为基础。切换基础预设后，未覆盖 token 自动获得
  新的层级；已保存的覆盖值不应被重写或迁移。
- 阅读画布处于“跟随应用主题”时继续继承新主题的背景和文字；自定义阅读画布只
  覆盖文章内容树，不得反向污染工具栏、侧栏、设置弹窗或主题预览。

## 无障碍与验收

### 自动化测试

1. 扩展 `frontend/src/utils/theme.test.ts`：验证四套预设的完整 token 契约、完整
   对比度报告、根节点背景同步、Auto 解析和现有浅深色语义均无回归。
2. 扩展 `ThemePresetPicker.test.ts`：验证新的壳预览 DOM、Auto 的双预览语义、
   内置主题顺序、单选键盘行为及选中状态；不把纯视觉色值当作唯一断言。
3. 为预览样式添加源级或浏览器断言：四套锚点都映射到对应缩略图，没有旧的三条
   色带结构或错误的色彩组合。
4. 在现有主题浏览器流程中逐个选择 Paper、Ink、Sepia 与高对比度，验证侧栏、
   抽屉、文章列表、设置弹窗、阅读画布、焦点态和主题持久化；再验证一个基于每
   套预设的自定义档案仍能继承和覆盖 token。

### 人工检查

在 1440px 与 390px 分别检查：主题选择器不溢出；选中项、键盘焦点、悬停与禁用
状态均清晰；阅读模式的自定义画布边界不变；Paper 与 Ink 的 Auto 切换不产生
短暂错误背景。对照四种预设检查正文、次要文字、活动项、警告信息和主按钮的
可读性。

`git diff --check` 和 `wails3 build`。本次不安装新依赖，也不修改后端、设置 schema
