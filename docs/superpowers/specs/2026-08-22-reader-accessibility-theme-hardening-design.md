# 阅读器主题与可访问性加固设计

## 目标

在不改变 MrRSS 已完成的三栏阅读器结构、阅读模式和五套内置主题的前提下，消除本轮 UI 审查暴露的高优先级问题：小字号状态文字对比度不足、代码高亮颜色未完全随主题变化、共享反馈组件仍使用固定色值、设置控件缺少可访问名称，以及移动端返回按钮没有语义名称。

## 已确认的产品决策

- 保留 `Paper`、`Ink`、`Sepia`、`High Contrast` 和 `Auto` 的现有主题模型，不增加用户编辑颜色 token 的设置。
- 阅读器的密度保持克制：文章元数据可紧凑，但不以低于可读阈值的字号和低对比度换取密度。
- 主题差异只通过语义 token 表达；共享控件不再直接依赖 Tailwind 的固定蓝、绿、黄、红色阶。
- 激活文章以完整的选中表面和细边界表达，不以仅左侧的强调条表达当前阅读位置。
- 移动端图标按钮必须同时具备可见提示和屏幕阅读器名称。

## 方案

### 主题语义层

全局样式新增以下稳定 token，并在 Paper、Ink、Sepia、High Contrast 中逐一覆盖：

- `--accent-foreground` 与选中文本前景色，保证强调色背景上的文字在所有预设中可读；
- `--state-info-*`、`--state-success-*`、`--state-warning-*`、`--state-danger-*`，用于提示、错误和危险操作；
- 代码高亮的注释、关键字、字符串、标题、属性、元数据和公式背景 token；
- 选择状态 token，避免 High Contrast 的黄色强调色配白字。

共享 Toast、设置错误态和危险操作消费这些 token。代码高亮在文章内容层统一覆盖 highlight.js 的默认色，而不是只对深色主题补丁，因此 Sepia 与 High Contrast 也有完整表现。

### 阅读密度与对比度

文章列表作者和日期使用 `text-text-secondary` 与至少 `text-xs` 的基准，不再将作者降为 `text-text-tertiary` 的 11px。窄桌面布局仍可以压缩标题的行数和间距，但不覆写元数据的可读字号。上一篇/下一篇导航取消透明度降级。

当前文章保留低干扰的表面色，同时用全边界的内嵌选中线表示焦点。正文引用块是内容语义，不作为导航状态处理，维持其独立的排版规则。

### 设置与移动端语义

`SettingWithToggle` 将设置标题透传为开关的 `aria-label`。`NumberControl` 接受同名属性并将其绑定到实际的 `<input>`，直接调用处提供本地化标签。移动端文章工具栏的返回按钮提供本地化 `aria-label` 和 tooltip 标题。

## 不在范围内

- 不重构设置页面的信息架构或增加偏好同步策略。
- 不逐项改写业务功能内的装饰色；本轮覆盖所有共享反馈与表单基础组件，业务页面遗留项另行收敛。
- 不删除文章正文中具有内容语义的引用样式。

## 验证

先为设置开关、数字输入和移动端返回按钮写会失败的组件测试。实现后执行相关单测、完整前端单测、ESLint、Prettier 检查和 Vite 生产构建。浏览器回归在桌面与 390px 宽度下运行 axe，验证设置页标签、移动端返回按钮和文章正文的颜色对比度。
