# 阅读模式导航与理解效率设计

## 状态

用户已确认立即执行。本规格将此前的阅读模式体验审阅落实为五个相互协作、但边界清晰的改动：工具栏、目录、翻译显示、外观面板和短文已读行为。

## 目标

让长文阅读时最常用的控制在桌面和移动端都能快速找到，同时不让工具栏、外观设置或翻译功能夺走正文的注意力。

## 已确认的问题与根因

1. 阅读模式顶部只展示一串图标。退出、查找、目录和外观属于阅读中的高频动作，但其中查找和目录没有可见入口；收藏、稍后读和在浏览器打开等低频动作与它们抢占同一层级。
2. `FloatingToc.vue` 只在 `min-width: 768px` 构建目录；小屏分支为空，因此配置打开浮动目录后手机仍没有目录入口。桌面目录文字主要依赖 hover，键盘操作时信息不足。
3. 工具栏在阅读模式隐藏翻译开关；已有 CSS 已能同时支持原文、双语和仅译文，但目前仅使用全局 `translation_only_mode`，不能在当前阅读会话快速切换。
4. 阅读外观面板把风格、字体、字号、密度、栏宽、画布色和预览平铺在一层；保存成功没有可见反馈。
5. `ArticleContent.getReadingProgress()` 在正文不需要滚动时返回 `100`。当 `mark_read_on_scroll` 开启时，这会把“刚打开且完整可见”误当成“已完成滚动阅读”，立即触发 50% 自动标已读。

## 方案选择

### 不采用：继续增加顶部单独图标

实现最小，但会继续扩大没有文字的工具栏，并迫使用户记住图标含义；在窄宽度下还会产生横向滚动。

### 不采用：为阅读模式加入持久侧栏

目录和操作虽更直观，但阅读模式会失去现有的单栏专注感，并挤压 58–72ch 的正文列。

### 采用：核心动作固定、更多操作按需展开

阅读模式顶部保留明确的 Exit、Find、Contents、Appearance 和 More 五类入口。More 采用局部、可关闭的菜单收纳文章状态和外部动作；目录在桌面作为现有浮动目录的展开状态，在手机作为底部抽屉。这样不会改变文章阅读的主布局，也让触屏和键盘路径完整可达。

## 交互合同

### 顶部工具栏

- 阅读模式的左侧退出操作保留 `toggle-reading-mode` 的现有语义，并以“退出阅读”文字在桌面呈现；小屏保持 44px 图标触控目标及可读名称。
- Find 和 Contents 在 RSS 正文阅读时可见。Find 复用既有 `FindInPage`；Contents 请求文章内容区域展开目录。
- `Aa` 仍打开现有外观面板。More 使用已有 Phosphor 图标体系，不引入新图标库，菜单中包括：切换原网页/RSS 正文、标为已读/未读、收藏、稍后读、在默认浏览器打开、翻译显示模式。
- 翻译显示模式有“原文”“双语”“仅译文”三个本地化选项。它只改变当前文章详情/卡片会话的渲染类，不写入 `translation_only_mode` 全局设置。翻译服务未启用时不显示这一分组。
- More 在点击外部、Escape、选择任何项目或离开阅读模式时关闭；触发按钮保留 `aria-expanded`、`aria-controls` 和焦点返回。
- 阅读进度仅在内容可滚动时显示；进度条改用 `transform: scaleX()` 而非 width transition，并在减少动态效果偏好下即时更新。

### 目录

- `FloatingToc` 无论屏幕大小都从文章标题构建同一份目录数据。桌面继续显示右侧浮动轨道，Contents 让文字、面板底和关闭路径保持可见，键盘不依赖 hover。
- 小于 768px 时，Contents 打开一个带遮罩的底部抽屉；抽屉有标题、关闭按钮、焦点约束、Escape、遮罩点击和安全区域底部留白。每个条目触控高度至少 44px，选择标题后平滑滚至正文并关闭抽屉。
- 无标题文章仍可打开 Contents，并清晰显示“没有章节”；不隐藏核心功能，也不伪造目录。

### 外观面板

- 面板首屏保持风格、字体、字号和阅读密度等“快速调整”。栏宽、阅读画布颜色和预览收进一个默认折叠的“高级外观”区域；手机仍不显示桌面无效的栏宽。
- 自动保存状态在标题旁或页脚使用 `aria-live` 说明“正在保存”“已保存”或现有的失败重试动作。连续调整在既有 500ms 合并窗口内保持“待保存/正在保存”，成功后才显示“已保存”。
- 保存状态不改变即时预览，也不改变现有失败后保留本地值、可重试的策略。

### 短文自动标已读

- 滚动容器有实际滚动范围时，仍使用其当前位置百分比报告并显示阅读进度。
- 没有滚动范围的短文不报告 `100%` 作为滚动进度，且顶部不显示误导性的完成条。
- 短文在阅读模式中连续可见 4 秒后，单独发出“阅读停留完成”事件；仅由现有 `useArticleReadTracking` 按 `mark_read_on_scroll` 策略处理。切换文章、退出阅读模式、组件销毁或文档隐藏都会取消计时器。
- 非阅读模式短文继续遵循既有打开文章策略，避免意外改变普通 RSS、网页和外部浏览器行为。

## 组件与数据边界

- `ArticleToolbar.vue` 负责阅读操作分层、More 焦点/关闭生命周期、外观保存状态传递；它只发出用户意图。
- `ArticleDetail.vue` 与 `ArticleDetailModal.vue` 拥有临时的翻译显示模式、查找和目录打开状态，并把操作转给 `ArticleContent` 或既有已读策略。
- `ArticleContent.vue` 仅负责正文的滚动可用性、短文停留计时和渲染类；它不直接写文章状态。
- `FloatingToc.vue` 负责相同目录数据的桌面浮动呈现与移动抽屉呈现；不新增全局状态或持久化设置。
- `useReaderTypographyPreferences.ts` 负责保存状态机和网络写入；`ReaderAppearancePanel.vue` 只展示状态并发出排版操作。

## 可访问性、响应式与主题

- 保持现有语义色 token、按钮高度和 `ui-button`/`ui-icon-button` 体系，颜色不是唯一状态信号。
- 目录抽屉和外观抽屉均为可关闭对话层，支持键盘焦点与 Escape；桌面菜单使用正确的 button/menu 语义和可见焦点。
- 桌面正文列继续限制在既有 58/72/88ch 范围；手机目录、菜单和外观控制不产生横向滚动，触控目标至少 44px。
- 动画只表示状态，使用 transform/opacity；`prefers-reduced-motion` 下不使用平滑滚动或进度动画。
- 英语和简体中文新增文案完全对齐。

## 测试与验收

1. 工具栏组件测试核心阅读操作、More 菜单的关闭/焦点、翻译模式 intent、不可滚动文章隐藏进度。
2. `FloatingToc`/`ArticleContent` 测试手机目录抽屉、章节选择、无标题空态、桌面展开文本与关闭。
3. `ArticleDetail` 和卡片详情测试从工具栏把查找、目录和翻译模式准确传入内容层。
4. 外观面板和偏好 composable 测试高级区默认折叠、手机栏宽隐藏、待保存/保存成功/错误重试反馈。
5. `ArticleContent` 测试短文不再报告 100% 滚动进度、4 秒可见停留只发出一次完成事件、取消条件生效；详情页将该事件交给既有已读策略。
6. 在 1440px、768px 和 390px 宽度做 Playwright 浏览器验收，覆盖键盘操作、触控路径、无横向溢出、进度与主题可读性。
7. 运行相关 Vitest、完整前端单测、Vite 生产构建、Go 测试和 Wails 构建。

## 非目标

- 不新增阅读历史、阅读时长统计、可调停留时间、后台同步或数据库迁移。
- 不修改全局 `translation_only_mode` 的设置页语义。
- 不更换当前主题、正文排版预设、RSS 翻译服务或文章内容安全策略。
- 不移除现有文章操作；仅重新安排其入口层级。
