# 阅读器交互与状态打磨设计

## 目标

让文章列表和原始网页阅读路径具备成熟桌面阅读器应有的连续性：鼠标、键盘和辅助技术获得一致的文章选择能力；列表在加载时保留稳定的阅读节奏；嵌入的原始网页拥有明确名称。

## 已确认的设计决策

- 文章条目继续保持现有紧凑列表布局，不改为卡片或新导航模型。
- 每个文章条目暴露为可聚焦的按钮语义，`Enter` 和 `Space` 与点击产生同一选择事件；当前文章通过 `aria-current` 表示。
- 列表工具栏保留图标优先的高密度设计，但每个操作使用本地化名称；仅未读筛选和筛选弹窗暴露其状态。
- 首次加载和切换筛选时使用固定尺寸的骨架行，避免只显示一个漂浮的旋转图标造成布局跳动。骨架是状态反馈，不是额外装饰。
- 原始网页 iframe 使用当前文章标题作为名称，阅读主视图和卡片模式弹窗保持一致。

## 范围

### 包含

- `ArticleItem` 键盘访问与当前项语义。
- `ArticleList` 工具栏状态、加载骨架和空列表可读标记。
- `ArticleDetail`、`ArticleDetailModal` 原始网页 iframe 名称。
- 对应的组件测试和浏览器 Axe 回归。

### 不包含

- 重构文章列表的数据获取或虚拟滚动。
- 更改文章筛选、已读和收藏的业务规则。
- 重做侧栏导航结构或添加新的用户设置。

## 验证

组件测试先断言文章键盘选择、工具栏状态属性和 iframe 标题，再实施生产代码。浏览器验证桌面与移动文章选择路径、骨架加载状态和 Axe 扫描；构建、格式检查与完整前端测试作为回归门槛。
