# 自定义应用主题设计

## 目标

在现有内置主题预设之上，为 MrRSS 提供灵活、可持久化的应用级主题编辑能力。用户可以选择系统已安装字体并调整应用颜色角色，同时保持文章正文的阅读设置独立，避免主题编辑器覆盖正文排版或文章自定义 CSS。

## 已确认的产品边界

- 主题设置作用于应用外壳：活动栏、订阅抽屉、文章列表、工具栏、设置页、弹窗、通知、媒体控件和阅读器表面。
- 文章正文的字体、字号、行距、宽度和排版仍由阅读设置控制。
- 现有自定义 CSS 继续只作用于文章内容，不扩展为全局应用 CSS。
- 内置预设 `Paper`、`Ink`、`Sepia`、`High Contrast` 和 `Auto` 保持可用且不可被用户直接修改。
- 用户可以创建多个命名自定义主题，并在主题之间切换、复制、重命名和删除。
- 应用字体只能从运行环境检测到的系统字体中选择；不加载远程字体，也不上传字体文件。

## 方案

### 主题档案模型

保留现有 `theme` 设置作为活动主题标识：内置主题使用原有值，自定义主题使用 `custom:<id>`。新增 `theme_profiles` 设置，以 JSON 字符串保存自定义档案数组。档案结构如下：

```ts
interface CustomThemeProfile {
  id: string;
  name: string;
  basePreset: 'paper' | 'ink' | 'sepia' | 'high-contrast';
  appearance: 'light' | 'dark' | 'auto';
  light: ThemeTokenOverrides;
  dark: ThemeTokenOverrides;
  uiFontFamily: string;
  uiFontSize: number;
  updatedAt: string;
}
```

`light` 和 `dark` 是稀疏覆盖对象。未填写的 token 从 `basePreset` 对应的完整 token 集继承，因此删除或损坏单个值不会产生半套主题。`appearance: auto` 根据系统颜色模式在两套覆盖之间切换；只有一套覆盖时，另一套仍从基础预设继承。

### 可编辑 token

编辑器按语义角色分组，而不是暴露组件私有选择器：

- **表面**：应用背景、侧栏、面板、悬停、选中、弹层。
- **文字**：主文字、次文字、三级文字、禁用文字。
- **强调**：强调色、悬停强调色、强调色前景、选择背景和选择文字。
- **边界**：边框和分隔线。
- **状态**：收藏、稍后读、信息、成功、警告、危险，以及未读徽标的前景/背景。
- **阅读器表面**：代码块、标记、表格条纹和媒体控件/查看器表面。

这些角色映射到现有 CSS 变量注册表。注册表是唯一允许写入根节点的变量集合；不提供任意 CSS 属性或选择器输入。派生色（例如状态背景、悬停色和 alpha 版本）由主题引擎生成或由对应的语义 token 覆盖，避免组件各自解释颜色。

### 设置交互

“常规 > 应用 > 主题”保留内置预设选择器，并增加自定义主题管理区：

1. “新建主题”要求名称并选择基础预设。
2. 编辑器提供浅色/深色分段控制、系统字体选择、应用字号和分组颜色控件。
3. 任何改动立即应用到当前窗口，保存采用现有自动保存流程。
4. 每个 token 可单独恢复继承值，档案可整体恢复基础预设。
5. 主题列表支持激活、复制、重命名和删除；删除当前主题后自动回退到 Paper。
6. 提供导出/导入 JSON 文件，导入前做版本、大小、字段和颜色校验；导入失败不改变当前主题。

编辑器使用 `radiogroup`、`tablist`、明确的颜色输入标签和键盘可达的操作按钮。颜色预览不能作为唯一状态提示，选中、焦点和校验状态同时使用文字/边框/图标表达。

### 可读性校验

主题引擎在应用前校验：

- 主文字与应用背景至少达到 WCAG AA 普通文字对比度（4.5:1）。
- 次文字、强调文字、状态文字分别显示对比度结果；不满足时给出具体的前景/背景组合和修复提示。
- High Contrast 基础预设的关键 token 不能被覆盖为低于 AA 的组合；保存时阻止这种覆盖。
- 所有颜色接受标准 `#RRGGBB` 或 `#RRGGBBAA`，统一转换为 CSS 变量值。

### 持久化与启动

- `theme_profiles` 通过现有设置 REST API 持久化；设置生成器负责后端定义、默认值和前端类型同步。
- 最近一次解析后的主题档案写入版本化 localStorage 缓存。启动脚本只读取经过 JSON/字段校验的缓存，在 CSS 加载前设置主题属性和变量，避免闪屏。
- 后端或缓存数据损坏时，丢弃损坏档案并回退到 Paper；不执行任何档案内的 CSS 或脚本。
- 旧版 `light`/`dark` 主题值继续规范化为 `paper`/`ink`。

## 不在本次范围

- 文章正文字体、字号、行距、阅读宽度和排版控件的重新设计。
- 全局任意 CSS 编辑器、组件选择器编辑器或远程主题代码执行。
- 上传/嵌入字体文件。
- 改造主题之外的设置页信息架构。

## 验收与测试

- 主题工具单测：档案 schema 校验、稀疏 token 合并、颜色规范化、对比度计算、损坏数据回退和旧值兼容。
- 组件测试：创建/复制/重命名/删除、浅深色编辑、字体选择、单 token/整档恢复、导入失败保护和无障碍语义。
- 设置 API 测试：`theme_profiles` 的 GET/POST 往返、大小/格式拒绝和部分更新。
- 浏览器测试：四个内置预设、至少两个自定义档案、系统浅深色切换、刷新持久化、移动端设置布局，以及侧栏/列表/弹窗/通知/媒体控件的一致性。
- 完成后运行前端单测、生产构建、Go 测试、lint/format、`git diff --check` 和可访问性扫描。
